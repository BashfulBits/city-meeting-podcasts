# Concise-prompt runtime reevaluation

The maintainer requested another evaluation with clear, nonduplicated prompts and repeatable
Python packet generation. `run-approval.json` records the fresh twelve-case run, capped at 48
single-attempt requests with no retries. Earlier results and their gold remain unchanged.

## Generate the packet offline

From the repository root, with normal development/LLM dependencies installed:

```bash
PYTHONPATH="$PWD" python evals/remedy/prepare_runtime_reevaluation.py \
  --approval evals/remedy/qualification/runtime-v2/run-approval.json \
  --output evals/remedy/results/runtime-qualification-2026-10-26/concise-v2/packet
```

The output directory must not exist. For a reproducibility check, generate into a fresh scratch
folder with the same command and compare the eight generated files byte-for-byte. Canonical
execution paths stay pinned by the approval even when preparation runs in a scratch directory;
a scratch build is not permission to execute another ledger. Two builds were byte-identical
before this run. A failed offline preparation was retained locally; no requests used that packet.

The script rebuilds source evidence from the retained inventory/cohort, checks approved references,
checks that expected decisions and deterministic validator results remain identical to the prior
approved draft, and emits initial payloads, provenance, expectations, source/prompt hashes, the
run plan and exact execution authority. It does not read credentials or contact a provider.
Generated artifacts remain ignored/local, not committed bulk.

`packet-audit.json` uses retained prior proposals only for deterministic sizing/duplication audits
of all twelve possible judge bundles. These are not new judgments or executable judge jobs.
Actual conditional judge packets are generated by the shared runtime factories from the new
initial responses. No expected decision, prior correctness or maintainer exception enters requests.

## What changed

Only the selected Flash/DeepSeek + Gemini/JEV plan uses the concise prompt revision. Legacy wire
prompts remain unchanged. All roles see the same source evidence and remedy policy. Initial chat
instructions are shorter and distinguish existing target-feed slugs from proposed new-feed metadata.
No new case-specific owner/archive policy or expected answer is inserted.

- Gemini receives one source-evidence object and one pair of untrusted candidate assignments.
  Archive context appears only when present, without another taxonomy/history/source copy.
- JEV receives a short choice instruction and one separate evidence object with A/B assignments.
  It keeps C (neither supported), D (insufficient evidence), and independent A/B probabilities.
- Neither judge receives route identities inside candidate data. The source taxonomy is retained
  in full exactly once. No evidence was dropped or silently truncated to fit.
- Changed JEV instruction/data changes its recipe hash. Reviewed runtime bindings also cover the
  context builder and prompt revision, preventing reuse of prior prompt qualifications.

The audit reduced the two previously oversized JEV bundles from roughly 44–45k estimated tokens
to 11,328 (RQ09) and 11,145 (RQ10). The largest across all twelve audited bundles is 11,328.
This is an estimate using prior proposals, not an actual provider token count for the new run.

Models/routes, schema, deterministic validator, exact consensus comparator, source evidence and
approved raw scoring expectations remain unchanged. RQ06's observed acceptance stays a separate
case-specific view. This reused challenge is not an independent production holdout.

The existing bounded `run_runtime_qualification.py` executor checks the newly generated authority,
source hashes and frozen payloads. It retains the fresh ledger's 48-attempt cap, one attempt per
case/role, 65-second provider spacing, 720-second deadline, 16,384 chat output cap, default reasoning,
no temperature override, primary accounts only, exact identity validation, owned provider pauses,
drain/reservations and owned-only restoration. JEV retains its native systemone wire.

```bash
PYTHONPATH="$PWD" python evals/remedy/run_runtime_qualification.py \
  --plan evals/remedy/results/runtime-qualification-2026-10-26/concise-v2/packet/run-plan-draft.json \
  --authority evals/remedy/results/runtime-qualification-2026-10-26/concise-v2/packet/execution-authority.json \
  --output evals/remedy/results/runtime-qualification-2026-10-26/concise-v2/measurement
```

Without `--execute`, this is offline preflight only. Execute solely through the approved suppressed
citypods-env credential wrapper; never repeat an active controller or an unresolved request.
A new access/profile/identity hold stops calls; this run has no retry allowance. Do not use a
secondary BeatAPI account, paid fallback, automatic Worker retries or another ledger.

Use `score_runtime_qualification.py` with the same plan/authority/output paths for read-only live
quality summaries. Compare the runs on identical answered-case intersections and report each
adjudicator's coverage; conditional case sets can change when initial responses change.
No production routing, remedy PR/issue creation, merge, deployment or activation is authorized.
