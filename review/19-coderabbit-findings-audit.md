# CodeRabbit findings audit

CodeRabbit was installed into this repo after most existing code was already written, so it had
never reviewed the bulk of the codebase. Rather than retroactively commenting on old merged PRs
(which only reviews each PR's frozen historical diff, and still needs the same staleness check —
not worth the effort relative to just reviewing current code), this audit runs CodeRabbit's CLI
directly against the **current state of every source file**, then verifies each finding against
the actual code before deciding whether it's worth fixing.

Findings are tracked here with stable IDs so they can be triaged and closed out over time, instead
of being a one-off comment dump. When a finding is fixed, update its row's Status to **Fixed** (+
PR link); don't delete the row — the table is the audit trail.

## How to run this review again

CodeRabbit (both the GitHub bot and the CLI) only reviews diffs — there's no native "scan the
whole repo" mode. The workaround: diff the current `HEAD` against a commit that has (almost) no
files, so the diff covers every tracked file in the tree.

**Prerequisites**
- `coderabbit` CLI installed: `brew install coderabbit` (Homebrew cask, official) — avoid the
  `curl | sh` installer on `cli.coderabbit.ai` when a package-manager path exists.
- Authenticated: `coderabbit auth login` requires a real interactive terminal (it opens a browser
  for OAuth) — run it yourself in your own terminal, not from an agent-driven shell, which will
  fail with "Non-interactive environment detected." (`auth login --api-key <key>` works headless
  if you have a key.)

**Procedure**
```bash
# 1. Find the repo's root commit and sanity-check it's still small relative to HEAD.
#    (If the repo's root commit already has hundreds of files, this trick doesn't buy you much —
#    look for a later commit that's still near-empty, or accept reviewing only the delta since then.)
root=$(git rev-list --max-parents=0 HEAD)
git ls-tree -r --name-only "$root" | wc -l   # should be small
git ls-files | wc -l                          # vs current file count

# 2. Run one scoped review per top-level source directory (smaller diffs = less noise, easier to
#    triage in batches; --dir filters the diff to that path).
coderabbit review --agent --type committed --base-commit "$root" --dir citypods \
  > .claude/coderabbit/full-review-citypods-$(date +%F).jsonl
# repeat per directory: scripts, tests, workers, templates, .github, …
```

Notes:
- **Use the root commit, not git's empty-tree SHA** (`4b825dc642cb6eb9a060e54bf8d69288fbee4904`).
  `coderabbit review --base-commit` runs a three-dot symmetric diff (`git diff base...HEAD`, via
  merge-base), which requires a real commit object — a bare tree SHA fails with `fatal: Invalid
  symmetric difference expression`.
- **Use `--agent`, not `--plain`**, when running this from inside an agent/CLI-driven shell — the
  CLI detects the environment and tells you to. `--agent` emits structured JSON; `--plain` is for
  a human at an interactive terminal.
- **Skip non-source directories** — `config/` here is per-city YAML *data*, not code, and
  `review/`/other docs are markdown; reviewing those just adds prose-style noise.
- Output is newline-delimited JSON: a `review_context` line, `status`/`heartbeat` progress lines,
  one `{"type":"finding", "severity", "fileName", "codegenInstructions", "suggestions"}` object per
  issue, and a final `{"type":"complete","findings":<n>}` line. Save the raw stdout to a file —
  don't rely on a UI task-pane preview, which truncates long output for *display* only; the
  underlying tool-call data is the full, untruncated stream.
- Every finding's line numbers point at *current* `HEAD` (not a stale historical PR), since the
  diff's "old" side is the near-empty root commit — but **still verify each one against the repo**
  before fixing; CodeRabbit can misjudge a codebase's actual invariants (see the "Invalid / by
  design" rows below for real examples: redaction that's already a no-op, merge truthiness that's
  the documented contract, etc.).
- Raw `.jsonl` outputs are saved under `.claude/coderabbit/` in the repo (untracked/gitignored
  locally) as `full-review-<dir>-<date>.jsonl`.
